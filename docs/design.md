# memo 設計と決定事項

2026-11-13。対象は個人・少人数。月額固定費と運用データを抑える。

## 仕様の扱い

[機能仕様 v0.2](spec-v0.2.md) は `tmp/` の原本から管理対象へ複製したもの。
ユーザーが置いた原本は残す。本書はその後の対話で合意した設計を記録し、
競合処理など矛盾する箇所では本書を優先する。実装済み範囲は
[先行検証の記録](validation.md) で確認する。設計決定と実装完了を混同しない。

## 技術構成

- TypeScript、Vue 3、Composition API、Vite。フロントはクライアント描画。
- Tiptap 3を第一候補。限定的な行ベースの変換を先行検証する。
  `@tiptap/markdown` は全文変換による原文の変化を避けるため現時点で採用しない。
- Hono、Lambda、API Gateway HTTP API。Web APIとMCPで本文更新処理を共用する。
- DynamoDBオンデマンド。キー検索と条件付き更新にアクセスを限定する。
- CloudFront、非公開S3、Route 53、通常のACM公開証明書。ホストは `memo.anipopina.com`。
- PasskeyはSimpleWebAuthnを予定。サーバー管理セッションをHttpOnly・Secure・SameSite付きCookieで扱う。
- pnpmの固定版とロックファイルを共有。ESLint、Prettier、Vitest、Playwright。
- CDKはインフラ実装時に導入。Piniaや大きなUIライブラリは現段階では追加しない。

## 本文とエディタ

Markdown文字列だけを正本とする。HTMLやエディタJSONは永続化しない。
行単位で本文を保持し、ハイフン・番号付きの箇条書きと入れ子を表示・入力支援の対象にする。
それ以外のMarkdownは文字として残す。空行、末尾改行、混在したLF/CRLF、空白、
未知の記法も、読み込みだけで正規化しない。リンクのmarkは表示専用で保存に影響しない。
本文のHTMLは実行しない。HTML貼り付けもプレーンテキストを優先する。

URLはhttp/httpsだけをリンクにする。PCはCtrl/Cmd＋クリックで別タブ、
通常クリックとタッチでは明示的な「開く」を出す。本体ではリンクを選んだときに、そのURL文字列の右上に
小さな別タブアイコンを表示する。アイコンは小さく見せてもタッチ範囲とアクセシブルな名前を確保する。
検証画面の「リンクを別タブで開く」ボタンは維持する。本体では以下の階層操作ボタンと併せて配置を調整する。

### 箇条書きの追加要件（2026-11-13）

ユーザーの追加依頼により、仕様v0.2の第6.2節にある「番号付き・入れ子の補助は要求しない」を変更する。

- `- ` または `1. ` のような数字・ピリオド・半角スペースでリストを開始する。
  入力時の番号はMarkdownに合わせて9桁まで。読み込んだMarkdownの番号、先頭ゼロ、インデント、区切りの空白は、読み込みだけでは書き換えない。
- Enterで同階層の次項目を作る。トップ階層は先頭項目の入力番号から数え、子階層は同じ親の項目ごとに1から数える。
  例えばトップを「2. 」で始めると次は「3. 」、その子は「1. 」から始める。
  表示番号は読み込み時からこの規則で計算する。階層変更・追加・削除などリスト構造を編集した場合は、
  その連続したリスト内のMarkdown番号も振り直す。別のリストは変更しない。
  外部同期とUndo/Redoでは受け取った本文・履歴をそのまま保持し、表示だけ階層別に計算する。
- リスト内のTabは直前の同階層項目の下へ1段下げ、Shift＋Tabは親階層へ戻す。
  親にできる先行項目がなければTabは変更しない。通常の文章ではTabによるフォーカス移動を維持する。
- 操作対象の子孫もまとめて移動する。複数項目を選択した場合はまとめて変更する。
- モバイル向けに「字下げ」「字上げ」ボタンを設け、Tab/Shift＋Tabと同じ階層変更処理を使う。
  通常の文章、親にできる先行項目がない字下げ、最上位の字上げ、IME変換中は該当操作を無効にする。
  タップ時に本文の選択とフォーカスを維持する。動作はiPhone実機で確認済み。
  検証用の本文上部へのインライン配置は本体へ引き継がない。対象行を見ながら操作できる配置を、
  「リンクを別タブで開く」と併せて本体で調整する。具体的な配置方式は未決定。
- 箇条書きの表示記号は1段目が `•`、2段目が `◦`、3段目以降が `▪`。保存するMarkdownはすべて `- ` のままとする。
  深さは親子関係から求め、既存の2スペースなどの字下げでも段階を判定する。
  記号・番号は `list-style-type` の文字列で指定し、対象Safariで対応差のある `::marker` の `content` 指定には依存しない。
- 新たな階層のインデントは原則4スペース。親の番号・区切りが長い場合はその本文開始位置以上を確保する。
  読み込んだ2スペースやタブを、操作していない行まで正規化しない。
- 空項目のEnterと項目先頭のBackspaceは、子階層なら1段戻す。
  最上位ではリストを解除して通常の段落に戻す。階層変更・終了は1操作ずつUndoできる。
  IME変換中は保存と外部更新反映を待機する。
  WebKitの空行IME確定時の行消失を避けるため、各行にposition指定による配置を使わない。
  記号は標準のCSSリストマーカーを使い、将来のリンクアイコンも編集行をpositioned要素にしない方法で配置する。
  背景・判断根拠と撤去条件は [IME検証記録](validation.md#実機の再確認とcssによる回避2026-11-13) を参照。
- 確定直後の改行欠落への対応として、ProseMirrorのSafari向けキー抑制期間を100msに短縮する。
  [pnpmパッチ](../patches/prosemirror-view@1.42.9.patch) を適用する。対象iPhoneで解消と確定時の誤改行がないことをユーザーが確認済み。
  検証結果と撤去条件は [検証記録](validation.md#抑制期間短縮の試験2026-11-13) を参照。

実行時の最大本文サイズは [共通定義](../packages/core/src/note.ts) に置く。
入力停止後の保存と継続入力中の定期保存、表示中の約3秒ごとの変更確認を予定する。
非表示タブでは停止し、復帰時に即時確認する。変更確認には小さいバージョンレコードを
利用し、本文は変更時のみ読む。DynamoDBの属性投影だけでは読み取り料金は下がらない。

## 競合処理：手動マージ画面を作らない

共通の保存済み本文、手元の本文、サーバーの最新本文から差分を自動統合する。
別箇所の変更は双方を残す。同位置への異なる挿入はサーバー側、保存する側の順に保持。
重複する置換・削除は今回保存する側を優先する。同一の変更は重複させない。

この規則はユーザーが明示的に許容した変更であり、元の仕様の
「無言のデータ消失を防ぐ」を完全な無損失保証とはしない。
同じ範囲の編集、削除と編集、大幅なAI書き換えでは一部が失われたり、削除が戻り得る。
計算量を制限した先行実装では大きい変更の競合範囲が粗くなるため、さらなる検証が必要。
文意の正しさまで保証するものではない。

条件付き保存は維持する。CAS失敗後に最新状態へ統合し直し、無制限には再試行しない。
重複範囲を調整した場合だけ控えめに通知し、ローカルに直前の本文1件を保持して
コピー可能にする。サーバー履歴や競合コピーのメモは増やさない。
他端末の変更は選択範囲をマッピングするトランザクションで反映し、Undo履歴へ混ぜない。
離れた複数変更をまたぐ選択やIMEは先行検証で確認する。

MCPの全文置換には期待バージョンを必須とし、衝突はAIへ返して再取得を促す。
追記は最新本文へ原子的に適用する。両方に操作IDを要求し、同一リクエストの再送を
重複適用しない。追記は改行を勝手に補わない。

## 遅延作成・遷移・オフライン

未ログインの新しいメモはブラウザのCSPRNGでトークンを生成する。
空表示ではサーバーに書かず、最初の入力、明示的な共有、一覧への引き継ぎで作成する。
ログイン中の新規作成は作成と一覧追加をまとめて行う。
不明な固有URLは404とし、閲覧だけで作成しない。

未ログインのトップ用メモ記録と、アカウント内の最後の選択を分離する。
固有URLの直アクセスだけではトップ用の記録と一覧を変更しない。
ログイン時は仕様の3分岐を維持し、未保存本文を先に保護する。

IndexedDBにタブ別下書きと基準バージョンを保存する。
通信が切れても開いている画面で編集を続け、再接続時に条件付き保存・統合を行う。
オフラインでの新規起動は初期版の保証に含めない。

## 最小UI

日本語UIを初期対象とする。iPhone SafariとWindows Chromeを優先する。
PCは折りたたみ可能な一覧と本文、スマホは本文と一覧ドロワー。
一覧は追加順の新しいものから並べ、編集で勝手に移動させない。
タイトル欄は設けず、最初の空でない行を表示名にし、空なら「無題」。
共有メニューにWeb/MCP URLのコピーをまとめ、保存状態は本文付近に表示する。
未ログインでは新規作成UIを出さず、ログイン中の一覧外メモだけに追加操作を出す。
システムフォント、十分な文字サイズとタッチ領域を使い、外部CDNに依存しない。

## セキュリティと低コスト運用

トークン検索はハッシュで行い、一覧からURLを復元するためのトークンを
AES-256-GCMで暗号化する。鍵はランダムな32バイトでLambda環境変数に設定。
暗号化ごとに新しい96ビットnonceを使い、認証タグとレコード識別子によるAADを利用する。
顧客管理KMS鍵、Secrets Managerは導入しない。Lambda既定の環境変数暗号化を利用する。
鍵はGit、CDKテンプレート、ブラウザ、ログに入れず、別途控えを保管する。
鍵の漏洩はURL流出に、鍵の紛失はURLの復元不能につながる。

本文の認可にアカウントIDを使わない。一覧参照と本文の権限は分離する。
Web APIは同一Origin限定。MCPはOriginなしを受け入れ、付く場合は許可値を検証する。
トークンのBase64URL表現は正規形まで検証する。

CloudFront/API Gatewayのアクセスログ、正常リクエストの記録、解析、
分散トレーシング、独自履歴、監視ダッシュボードは追加しない。
本文・トークン・Cookie・生URLを記録せず、安全なエラーだけ短期間保存する。
Referrer-Policy、本文のno-store、CSP、検索除外、Origin検証と入力検証を適用する。

NAT Gateway、ロードバランサー、単独契約WAF、常時稼働サーバーは使わない。
APIのスロットリングと作成・更新のアプリ側レート制限を設ける。
CloudFrontの無料プランは公開時に適用条件を確認する。
S3とCDKの古い成果物を無制限に残さない。DynamoDB PITRのみをバックアップ候補として残す。
API Gateway、DynamoDBオンデマンド、保存容量、ログ、PITRには少量でも従量費が発生し得る。
無料枠はアカウント全体の利用と契約条件に依存し、料金ゼロは保証しない。

## MCPと公開境界

Streamable HTTP、ステートレス、JSON応答を基本とする。
共通のサーバーがURLの1メモだけへアクセスし、ツール引数で対象を変更できない。
公式SDKクライアントによるローカル検証と、ChatGPTによる公開HTTPSでの実機検証を分ける。
SDKが対応するプロトコル版を記録し、未確認のクライアント対応を保証しない。
互換コードは対象クライアントで必要と確認した場合にのみ追加する。

ローカルのメモリストアは検証専用。公開には永続DB、認証、レート制限、
秘密情報・ログ・キャッシュ設定を含む本体を用意する。
コミット・デプロイ・公開HTTPSへの露出は明示的な依頼なしでは行わない。
